# Two-minute demo — UNLOCKED

**0:00–0:20 — The constraint.** Show the overview. “Three organizations want to help one person. HCMC commits five million VND for medicine. Hanoi commits five million for medicine or education. Melbourne commits two million, but insists on an independent reviewer. Today, pooling this money usually means trusting one controller.”

**0:20–0:40 — Conditions travel with capital.** Open funding commitments. “TrustVault keeps each organization's mandate attached to its contribution. Shared purpose does not erase independent authority.” Use the seeded travel draft and propose it: show HTTP 422. “Even an Admin cannot turn medical funding into unrestricted spending.”

**0:40–1:10 — One transaction, three voices.** Open the valid twelve-million medical draft as HCMC User. Propose it. Show the funding allocation, beneficiary account and evidence reference. Sign in as each organization's Analyst and approve. “Each decision is bound to this exact amount, destination, evidence and funding allocation. Melbourne's reviewer is different from the requester.”

**1:10–1:30 — Authority before settlement.** Show missing approvals before the final approval, then the Authorized state. Simulate settlement. “Only after all contributing organizations approve does the simulated ledger settle. There is no bank connection.”

**1:30–1:50 — Test the claim.** Open Security lab and run scenarios. Show actual HTTP 401, 403, 409 and 422 results, successful settlement, amendment invalidation and replay rejection. “These are real backend requests, not an animated success screen.”

**1:50–2:00 — Why Tide matters.** “This prototype demonstrates the policy, but its centralized backend remains trusted. Tide's Emergent Authority is our path to cryptographic enforcement beyond one administrator. We retrieved Raziel guidance; the Midgard provisioning issue blocks live integration. We will not call mock approvals Tide signatures.”

Preparation: use a fresh local seeded database, or run the repeatable Security lab first. Manual approvals require signing out/in between organizations. The lab adds synthetic funds and retains history; it restores the original identity when finished. No real beneficiary information should be shown.
